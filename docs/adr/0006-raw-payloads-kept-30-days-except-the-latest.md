# Raw Payloads kept 30 days, except the latest per Post and Handle

Although the Raw Payload is the source of truth (ADR 0003), we keep each one only 30 days after it was fetched (a per-Platform setting). The exception is the latest Raw Payload of each Post and each Handle, which stays as long as the Post or Handle data does. Normalized data (Posts with their Metric Snapshots, and Handle Snapshots) is kept 2 years from when it was collected, also a per-Platform setting. Platform rules such as YouTube's 30-day limit override both. Raw Payloads are stored as `jsonb`, meaning content-equal JSON, not byte-for-byte, with the fetch time and API version next to them.

We chose this to keep the database small and simple instead of keeping every fetch forever (~150 GB/year at 500 Handles) or adding a second byte-exact store of whole API responses. The cost: a mapping fix or a new fixed field can only be re-derived from the last 30 days of fetches plus each Post's latest payload. A catch-up Collection Run with a Tracking Window Override can refresh older Posts and add a new Metric Snapshot with today's counts. Past Metric Snapshots can't be recovered, because Platforms only report current lifetime totals. Don't "fix" this by extending retention without weighing that storage cost. See [the decision](https://github.com/rahmed12/socialMediaHarvester/issues/14).
