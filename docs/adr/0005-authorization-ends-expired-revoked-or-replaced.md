# An Authorization ends as Expired, Revoked or Replaced, and only Revoked deletes data

An Authorization is Active until it ends in one of three ways. **Expired**: the token stopped working without the owner withdrawing consent; Public Data collection continues and nothing is deleted. **Revoked**: the owner withdrew consent (or Meta's deauthorize callback arrived, or staff disconnected or removed the Handle); tokens are wiped and revoked at the Platform, and that Platform's deletion rule applies (YouTube: Private Data fetched under it deleted within 7 days, and its Public Data falls back to the 30-day plain-Handle cap). **Replaced**: a newer Authorization took over the same Handle; tokens are wiped and nothing is deleted. Google reports expiry and revocation with the same `invalid_grant` error, so we treat it as Expired and automatically move it to Revoked after 30 days without a reconnect, matching YouTube's 30-day re-check rule.

This replaces the earlier rule that an Authorized Handle "reverts to a plain Handle and keeps its history", which contradicts YouTube's terms. We rejected deleting on every token failure, because ordinary token expiry would destroy data the owner never asked to remove. We also rejected keeping everything forever, because that breaks YouTube's terms. Each grant is a new Authorization so that Metric Snapshots keep pointing at the Authorization they were fetched under. See [the decision](https://github.com/rahmed12/socialMediaHarvester/issues/12).
